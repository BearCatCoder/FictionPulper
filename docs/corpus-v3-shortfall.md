# Corpus-v3 Shortfall Diagnosis

The versioned issue #20 evidence is
[`experiments/fictionpulper-corpus-v3-shortfall-v1/shortfall-report.json`](../experiments/fictionpulper-corpus-v3-shortfall-v1/shortfall-report.json).
It is generated by `src/report_corpus_v3_shortfall.py` from the hash-locked
inputs in `configs/corpus-v3-shortfall-v1.yaml`.

## Result

The base-only build considered 4,362 Corpus-v2 records containing exactly
30,004,706 tokenizer-v1 document tokens. It retained 1,947 records and
14,923,683 tokens and rejected 2,415 records and 15,081,023 tokens. The
exclusive first-reason breakdown is:

| First reason | Records | Tokens |
| --- | ---: | ---: |
| `invalid_schema` | 1,841 | 9,900,936 |
| `incomplete_creator_evidence` | 214 | 1,282,487 |
| `quality_review_required` | 314 | 3,337,005 |
| `prohibited_text_signal` | 46 | 560,595 |

There were no external inventories or acquisition attempts, so external
availability is unknown rather than zero. There were no acquisition failures,
exact-duplicate losses, near-duplicate candidates, length-filter losses,
boundary-filter losses, or concentration-selection losses in the current v3
funnel. Genre is a corpus-level gate rather than a row filter. Quality signal
counts overlap and are labeled non-exclusive in the machine report.

The report separately preserves the historical Corpus-v2 upstream rejection
counts: 1,281 exact duplicates, 558 low-confidence collections, 244
medium-confidence collections, 336 too-short/front-matter candidates, 93
probable novel/chapter candidates, 88 too-long candidates, 21 possible whole
books, 16 insufficient-prose candidates, 11 damaged-OCR candidates, two poetry
candidates, and 161 reviewed near duplicates. These are not current v3 funnel
losses. Exact tokenizer-v1 counts were not retained for those rejected
candidates, so their token yield remains unknown rather than estimated.

## Root Cause

The largest loss is an evidence-migration gap, not demonstrated over-rejection
of valid fiction. The 1,841 `invalid_schema` records are the legacy Corpus-v1
portion of Corpus-v2:

| Legacy source | Records | Tokens | Disposition |
| --- | ---: | ---: | --- |
| Project Gutenberg | 1,134 | 8,170,457 | Conditional recovery candidate |
| Seed corpus | 707 | 1,730,479 | Unavailable without source-byte, rights, and hash evidence |

All 126 source IDs behind the 1,134 Gutenberg rows join to the existing
hash-pinned Corpus-v2 source manifest. If each story is reproducibly linked to
the exact source bytes, its boundary is revalidated, and its rights evidence is
independently validated, the existing text and metadata filters classify 979
records and 6,954,543 tokens as otherwise eligible. The remainder still
requires quality review, creator evidence, or prohibited-boilerplate exclusion.
This is a measured conditional opportunity, not admission or approval.

The 707 seed records have neither source URLs nor source hashes in the sealed
input. Assigning them recoverable yield without recovering and validating the
original source evidence would violate the stop condition.

## Source Opportunities

Historical Corpus-v2 evidence identifies 244 medium-confidence Gutenberg
collections with 2,174 extracted candidates and 558 low-confidence collections
with 46 extracted candidates. These are ranked source-review hypotheses, not
yield estimates. No exact candidate token counts or post-deduplication,
post-quality acceptance rates exist, so their token ranges remain explicitly
unknown. New external catalogs likewise remain unknown until issue #21 runs a
bounded rights, boundary, duplicate, quality, and token-yield pilot.

## Attainable Size

The current individually eligible supply is exactly 14,923,683 tokens. A
bounded provenance-only scenario spans 14,923,683 to 21,878,226 tokens, with
the endpoint requiring the validated Gutenberg provenance migration and every
existing integrity gate. It is not a full current-pool upper bound: outcomes
for the creator-evidence and quality-review queues remain unknown. Even that
scenario endpoint leaves 28,121,774 tokens to Data50M, and the gross current
candidate pool contains only 30,004,706 tokens.

- Data50M from the current pool: **unsupported**.
- Data100M from the current pool: **unsupported**.
- Data50M or Data100M after external acquisition: **unknown**.

This is not a training-ready range. Corpus-v3 still fails genre distribution:
57.0408% of retained tokens are unclassified against a 35% maximum. Its 32
deterministic review records also remain pending. A forecast is not an
experiment GO.

## Decision

The single next action is a bounded provenance-recovery pass for the 1,134
legacy Gutenberg records: join their 126 source IDs to exact hash-locked source
bytes, verify reproducible text derivation, revalidate story boundaries, and
validate rights evidence. This tests the largest measured current-quality
opportunity before commissioning external expansion.

Rights, source hashes, exact and fuzzy duplicate review, split leakage,
creator and collection concentration, quality and OCR review, high-confidence
story boundaries, genre coverage, and deterministic human review remain
mandatory. Diagnosis does not make Corpus-v3 training-ready and does not alter
the sealed Data30M baseline.
